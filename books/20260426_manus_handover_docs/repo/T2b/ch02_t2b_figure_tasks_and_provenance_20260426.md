# T2b 第2章图表任务与来源追踪文件

## 一、使用说明

本文件服务于 T2b 第2章《机器学习不是控制的替代，而是认知层的扩展》的正式写作、插图执行与后续审校。其目标不是简单罗列“需要配图”，而是把本章中承担解释功能的图、表、公式和案例框逐项转化为可执行任务，并为每一项建立来源状态、治理要求与科学性复核条件。由于本章承担的是前半卷的方法论奠基功能，因此图表必须首先服务于“对象映射—门禁—责任链”的解释，而不是追求炫技视觉效果。

## 三、每个任务项的详细执行约束

### 3.1 Fig-1 机器学习在 CHS 中的位置图

该图必须帮助读者立刻区分两件事：第一，机器学习扩展的是感知、解释、检索与建议等认知能力，而不是直接替代控制器或执行器；第二，认知输出只有经过规则校验、物理校验、权限过滤与人工复核，才可能进入下游动作链。图中不应出现“模型直接控制闸门/泵站”的误导性箭头。

### 3.2 Tab-1 七类典型任务与工作链位置表

该表是本章最重要的教材化工具之一。它应避免把任务写成算法名词清单，而应围绕“任务作用于何种对象、输出进入哪一级工作链、是否带有门禁、失败后如何回退”来组织。表中所有术语应与第4章 Skill 编排和第6章授权治理保持一致。

### 3.3 Fig-2 对象—任务—责任三元映射图

该图负责承接本章第二轮扩写部分。图中至少需要展示三层关系：物理对象层、运行任务层、责任角色层。应避免把对象画成静态资产目录，而要体现对象在不同任务与责任链中发生语义重组的过程。

### 3.4 Eq-1 工程问题定义结构表达

该表达不应伪装成来自单一外部文献的既有标准公式，而应明确标注为本书用于教学组织的“问题定义框架”。建议采用“输入 X + 边界 B + 门禁 G + 角色 H + 回退 R → 输出 Y”的半形式化写法，并在图注或脚注中说明其属于作者归纳表达。

### 3.5 Box-1 告警分拣案例框

案例框应服务于方法论澄清，而不是讲完整项目故事。其核心是说明为什么高 F1 值并不自动降低认知负担，为什么事件链、起因/后果区分、优先级与责任触发才是真正决定工作质量的因素。案例宜保持抽象，不点名真实工程项目。
