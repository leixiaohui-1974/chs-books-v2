# T2b 第6章图表任务与来源追踪文件

## 一、使用说明

本文件服务于 T2b 第6章《授权边界、人工接管与平台治理：认知代理不能越过哪条线》的正式写作、图表执行与后续审校。其核心任务，是把本章最容易停留在抽象治理口号层面的内容，压缩成可以画出来、核对出来、执行出来的授权与接管结构。由于本章承担整卷前半部的制度收口功能，因此所有图表都必须服务于三个目标：第一，让读者看见授权层级；第二，让读者看见接管路径；第三，让读者看见平台治理如何把状态链、证据链和责任链正式收束。

## 三、每个任务项的详细执行约束

### 3.1 Fig-1 代理授权分层图

该图必须帮助读者理解：授权不是一个“开/关”开关，而是按任务风险、上下文条件和角色资格逐层配置的结构。图中至少要区分观察层、建议层、触发层、执行准备层和动作执行层，并明确哪些层只能由系统建议，哪些层必须由有权角色确认，哪些层根本不应由认知代理直接触及。

### 3.2 Fig-2 人工接管路径图

该图不能只画一个“人工接管按钮”。更合理的表达，是把接管展示为一条完整路径：异常被发现，异常被判断，接管被授权，输出被覆盖或停止，系统进入安全态，随后保留证据并进入复盘。因此，图中必须同时存在异常识别点、权力切换点、安全收口点和复盘入口点。

### 3.3 Tab-1 五类治理权力对照表

该表是本章最重要的教材化结构之一。覆盖权、停止权、回退权、审计权和追溯权不能被混写。每类权力都应说明由谁持有、何种条件触发、影响哪一层对象与状态、是否形成正式留痕，以及与第5章冲突消解权限之间的映射关系。

### 3.4 Fig-3 平台治理收口链

该图负责把本章所有治理概念最终收束到一个平台级视图中。应明确显示：代理输出不是终点，而是进入状态版本管理、证据留存、人工覆盖、审计记录和责任追溯的起点。图中必须避免把平台治理画成单条日志箭头，而应体现链与链之间的耦合。

### 3.5 Box-1 平台部署案例框

案例框应说明：即便某个代理在建议质量上表现优异，也不意味着它应被直接授权进入动作链。案例的重点应放在“能力很强但边界错误”的危险性上，而不是突出模型失误本身。表达方式宜保持抽象和平台化。

## 六、下一步动作

本文件建立后，T2b 第6章已经具备“证据卡—来源笔记—图表任务与来源追踪”三件套。第三轮精修前，应优先完成三项工作。第一，把 Fig-1、Fig-2 与 Fig-3 画成可执行草图，因为它们共同决定前半卷治理语言的最终形态。第二，把 Tab-1 的五类治理权力与第5章冲突消解权限逐项映射，形成跨章治理术语表。第三，在本章图注或脚注中明确区分哪些表述直接来自法规要求，哪些是作者针对 CHS 平台所做的归纳扩展。
