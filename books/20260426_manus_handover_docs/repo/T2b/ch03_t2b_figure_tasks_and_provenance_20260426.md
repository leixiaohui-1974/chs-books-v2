# T2b 第3章图表任务与来源追踪文件

## 一、使用说明

本文件服务于 T2b 第3章《快思考、慢思考与运行解释：认知引擎如何真正帮助调度员》的正式写作、配图执行与后续审校。其核心目标，是把本章中最容易被误写成“模型能力展示”的内容，重新压回到工作流、解释责任与人机协作设计上。换言之，本章图表必须帮助读者看到：认知引擎的价值不在于“回答更像人”，而在于能否把推理、证据、规程、角色和回退路径组织成真实可用的解释链。

## 三、每个任务项的详细执行约束

### 3.1 Fig-1 快工作流与慢工作流对照图

该图必须避免把“快/慢”画成两个模型框或两个参数规模。更合理的做法是把它画成两条不同节奏的解释工作流：快工作流偏向即时筛查、提示、检索和局部判断；慢工作流偏向证据复核、规程核对、角色确认和回退判定。图上应清楚标出人工介入点和责任确认点。

### 3.2 Tab-1 解释链五环节与责任对象表

该表是本章最重要的教材化元素之一。它应帮助读者理解解释并不是“语言展开”，而是一种责任组织。每个环节都应写明服务对象，例如值班员、会商主持者、审批角色或执行角色，从而避免“解释面向所有人却不真正对任何人负责”的泛化风险。

### 3.3 Fig-2 规程理解三层结构图

规程理解之所以不同于通用问答，在于它必须同时满足版本正确、角色匹配和适用条件成立三项约束。该图应将三层条件结构化表达出来，尤其要提醒后续章节不要把规程文本检索误写成简单知识问答。

### 3.4 Box-1 错误会商建议案例框

案例框的任务不是展示模型错误本身，而是展示“解释看起来很完整，为什么仍然危险”。因此必须突出至少一个关键遗漏条件，例如设备检修状态、上轮会商结论、授权等级或 ODD 边界，从而使读者理解解释链一旦缺少上下文与责任对象，就会形成伪解释。

### 3.5 Fig-3 四类误判定位图

该图可作为第三轮精修的增强项。它应把过度概括、上下文遗漏、角色错配和责任漂移分别挂接到“检索—推理—解释—交付—执行准备”链条中的不同位置，以便读者看到这些错误并不是随机出现，而是工作流结构问题的可定位后果。

## 六、下一步动作

本文件建立之后，T2b 第3章已经具备“证据卡—来源笔记—图表任务与来源追踪”三件套。第三轮精修前，最应优先推进两项工作。第一，把 Fig-1 与 Fig-2 形成草图版本，以便它们成为前半卷通用解释接口。第二，把 Tab-1 中的解释链环节与第4章 Skill 调用链进行术语统一，从而避免同一流程在不同章节出现多套命名。
